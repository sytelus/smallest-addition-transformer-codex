## 1) Final selected model

- Architecture: decoder-only transformer (`src/model.py`)
- Config:
  - `n_layer=1`
  - `d_model=8`
  - `n_head=2`
  - `d_ff=12`
  - `dropout=0.0`
  - `max_seq_len=23`
  - `vocab_size=114`
- Total params: **1,644**
- Final measured test (seed-123 holdout split): **0.9904 exact-match** on 10,000 examples.

Why this was chosen:
- It is the smallest config in this run history that cleared >=99% exact-match on the required 10k held-out test.
- Smaller nearby configs failed materially (see boundary section below).

## 2) Exact tokenization / formatting

Defined in `src/data.py`.

### Vocabulary
- Digits: `0..9` (10)
- Pair tokens: `P00..P99` (100)
- Specials: `=`, `<bos>`, `<eos>`, `<pad>` (4)
- Total = 114

### preprocess(A, B)
- Zero-pad each operand to 10 digits.
- Reverse digits to LSD->MSD order.
- For each column `i`, emit `P(a_i,b_i)`.
- Prompt: `<bos> P(a0,b0) ... P(a9,b9) =`

Example:
- `A=123`, `B=45`
- padded: `0000000123`, `0000000045`
- reversed digits start with: `(3,5),(2,4),(1,0),(0,0),...`
- prompt starts: `<bos> P35 P24 P10 P00 ... =`

### Target / generation
- Target tokens are reversed 11-digit sum + `<eos>`
- If `C=A+B`, target digits are `c0..c10` in LSD->MSD order.

### postprocess(model_output)
- Read generated digits until `<eos>` or non-digit.
- Keep first 11 digits (pad zeros if short).
- Reverse and parse int.

## 3) Capacity boundary observed

From run logs/metrics used in this repo report:

- **Smallest working:** `d=8, L=1, h=2, ff=12` => **1,644 params**, best val EM 0.9935, test EM 0.9904.
- Near boundary failures:
  - `d=8, L=1, h=2, ff=11` => 1,627 params, best val EM 0.7335.
  - `d=8, L=1, h=2, ff=10` => 1,610 params, best val EM 0.1705.
  - `d=8, L=1, h=2, ff=8` => 1,576 params, best val EM 0.6875.
  - tuned long attempt at `ff=8` still failed.
- Non-boundary references:
  - `d=8, L=1, h=2, ff=16` => 1,712 params can reach 1.0000 val with longer schedule.
  - `d=7, L=1, h=1, ff=14` => 1,442 params stalled low.
  - `d=6, L=1, h=2, ff=12` => 1,188 params essentially failed.

Interpretation:
- Sharp transition around ff width between 11 and 12 at `d=8, L=1`.

## 4) What failed / dead ends

- Original raw-digit formatting (`<bos> A_rev + B_rev =`) under tiny models plateaued badly.
- Very low-width models (`d<=7`) did not reliably enter high-accuracy regime.
- Reducing FF below 12 at `d=8` consistently underperformed, even with longer tuning attempts.

Do not repeat unless testing a new optimization/data trick; these were already low-value in this search trajectory.

## 5) Hyperparameter sensitivity noticed

- Boundary models are schedule-sensitive.
- Working config used:
  - `lr=3e-3`, warmup 100, cosine decay to 0.1*lr, `batch=512`, `steps=5000`.
- `ff=12` required enough steps to cross threshold; under-training looks deceptively close.
- `ff<=11` did not recover to target under comparable or longer runs in this search.

## 6) Known failure mode of final model

Errors are mostly carry-related off-by-one mistakes in middle/high digits.
Typical pattern: one wrong digit in reversed output, often where carry propagation chain is long.
See `results/final_results.json` for concrete examples.

## 7) Reproducibility-critical seeds and splits

- Main training/eval seed used for selected model: **123**
- Holdout split file name pattern: `holdout_v{val}_t{test}_seed{seed}.pt`
- Final reported test here uses seed-123 split generated by `src/data.py` holdout logic.

## 8) Recommended next experiments (to beat current result)

Priority order:
1. Keep `d=8, L=1` and test micro-architectural changes with same/better params:
   - Remove some biases / simplify attention projections.
   - Try smaller positional embedding strategy (or fixed sinusoidal) if it cuts params.
2. Explore tokenization variants that preserve pair-column locality but reduce vocab/embedding burden:
   - Factorized pair representation with tiny learned composition.
   - Carry-augmented prompting without leaking answer.
3. Optimization-only boundary push on `ff=11`:
   - longer schedule, different min LR ratio, gradient noise scale changes, EMA checkpointing.
4. Multi-seed robustness report at fixed config to ensure selection is not seed-lucky.

Guardrails:
- Keep strict holdout leakage prevention.
- Preserve deterministic preprocess/postprocess.
- Keep test size at >=10,000.
